# Freeze policy and study status

**Updated 2026-11-17 Pacific. The new study is in development. It has no active test freeze.**

## 1. Historical freeze

`simulation-freeze-1` belongs only to the completed view-selection study.
Its [manifest](FREEZE.md), [addenda](FREEZE_ADDENDA.md), pinned files and results remain historical evidence.
The tag and its hashes must not change to make the original protocol appear stronger.

The earlier test is spent. Every later method treats those images as development data.

The old freeze did pin code and analysis. It did not establish a useful research comparison.
The design had little selector headroom and could not distinguish selectors by false removal on its completed test data.
The ranker's target and history terms also restricted the conclusion.

Those limitations motivate a new method. They do not justify altering old outcomes.

The record also includes a pre-freeze test-seed incident, a self-addressed timestamp exception and later exploratory analyses.
The private packet still lacks the original timestamp message.
It must not claim independent registration or an instructor-held pre-test timestamp.

The historical gate remains available for reproducing the old study.
Passing it does not authorize new collection or validate the new method.
New code must use a distinct study identifier, data namespace and manifest.

The v1 pilot runner accepts only `support-dev-pilot-v1`.
The stress runner uses the separate identifier `support-stress-dev-v1` and must reject any test identifier.
A new confirmatory launcher is not implemented yet.

## 2. Development is open

Development permits changes to prompts, labels, thresholds and method details with dated records.
Every image inspected for those choices remains development data.
Development findings must not be described as confirmatory tests.

The active design is [METHOD.md](METHOD.md) with [EVALUATION_PLAN.md](EVALUATION_PLAN.md).
The old [EXPERIMENT_PLAN.md](EXPERIMENT_PLAN.md) and [SIM_PREREGISTRATION.md](SIM_PREREGISTRATION.md) remain pinned historical documents.
The new plan does not inherit their thresholds, seeds or test authorization.

## 3. Readiness requirements

Before a new freeze, the researcher must resolve each item:

- The contribution differs from the closest work under the researcher's slot rule.
- The input audit and support-label audit pass on development data.
- The verifier passes declared same-view and clear-state capability checks before gate calibration.
- Independent validation checks support labels without model outcomes. Use programmatic certificates, a declared human audit or a validated external reference.
- The required controls run and retain every outcome.
- Support diagnostics establish error-reduction opportunity for veto, or recoverable abstentions for cascade.
- A credible image-only comparator and appropriate change-detection controls test the claimed benefit.
- The method, prompts, model revisions and finite calibration procedure are complete.
- The researcher records reasons for the primary comparison, utility margin and class resolution floors.
- The arrangement weights, sample size and statistical procedure are fixed.
- The generator, nuisance settings, exclusions and reserve rules are fixed.
- The fresh split excludes all previously inspected arrangements and their derivatives.
- Both simulator versions of an arrangement remain in one split. Transfer evaluation keeps method settings fixed.
- The input boundary and new study-identifier checks pass before any test geometry exists.
- The professor reviews the scientific question and course scope.

A favorable pilot is not a substitute for these checks.
Failed readiness checks remain recorded. The researcher revises development or stops the direction.

The active study uses Isaac Sim and MuJoCo. It requires no physical-camera collection.
Programmatic physical-state labels do not automatically validate support judgments.
Each support certificate must name its input scope and the property it establishes.

## 4. New freeze record

The eventual record needs a new identifier. This document does not create one.
It must list exact code, configuration, dependency, checkpoint and prompt hashes.
It must bind the declared analysis and complete collection manifest to that study.

It must include the label rules and the predeclared integrity checks.

The researcher must authorize the commit and the final test launch separately.
This repository does not commit or push without the researcher's instruction.
Before test generation, retain a verifiable timestamp of the final manifest outside the working checkout.

Record who holds it and whether the timestamp is independent.
The earlier missing timestamp must not become evidence for the new study.

The launcher must check the new manifest and study identifier at generation, rendering and scoring.
The development path must not accept a test identifier.
Tests of these checks must use synthetic fixtures, never reserved test seeds.

Operational logs must expose only integrity information before the declared outcome release.

These are implementation requirements. This document is not an executable gate or proof that the requirements pass.

## 5. After the new freeze

A change needs a dated addendum that records what data and outcomes were already seen.
A material method, label or endpoint change retires the confirmatory claim on exposed data.
A new confirmatory evaluation needs a new record and fresh data.

An implementation correction requires an explicit impact assessment and a documented continuation decision.

Report all valid declared outcomes, including negative results.
Label additional analyses as exploratory. Keep the original analysis alongside them.
Never repair a historical record by silently changing its hashes, date or interpretation.
