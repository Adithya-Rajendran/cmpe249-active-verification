# sim/: simulated shelf rig

End-to-end commands, hosts, data layout and known gaps: [`docs/REPRODUCE.md`](../docs/REPRODUCE.md).

## What it is for

- **Camera-position design.** Check drafted arc stops and occluder placements on a 3-D model before taping stops or
  cutting occluders. Questions it answers: does the occluder hide the mug from this stop, are #3 and the tags inside
  the frame, how much margin is left?
- **Visibility labels.** Per-object visible fractions and H/C/p classes for candidate views, from exact segmentation.

- **Isaac Sim is the study's simulator; MuJoCo is the cross-check.** The MuJoCo backend stays as an independent geometry check, run on request only (student, 2026-11-02).
- **The course study's test bed (decision 2026-11-02).** The student moved the study from physical capture to
  simulation ([`docs/SIMULATION_STUDY.md`](../docs/SIMULATION_STUDY.md)). Realistic images then come from the Isaac Sim
  backend, and both backends give exact labels.

**MuJoCo is not an appearance model.** Its colours are flat render defaults, and textures, materials, lighting, lens
blur, noise and the real props are not modelled. Do not read detector scores, DINOv2 matches or "how the photo will
look" from a MuJoCo render; use the Isaac Sim backend for appearance.

## Coordinate frame

The frame is in metres and right-handed, as in `configs/rig_geometry.json` → `frame`:

- **x** is lateral, + right as seen from the camera, 0 on the #3 centre line.
- **y** is depth behind the #3 front plane, + into the shelf.
- **z** is height above the mug-shelf top (the top of #3's floor board).

The analytic design scripts (`geom_measured.py`, `geom_far.py`) use cm with (x_a lateral, y_a height, z_a depth), so
`(x, y, z) = (x_a, z_a, y_a) / 100`. "The mug at z = 24" in `design_far.md` is `load_rig(..., mug_z=0.24)`, the
mug's y coordinate.

Positions drafts (`cmpe249.positions.v1`) place the lens on an arc of radius R about a centre on x = 0, at
`arc_centre_behind_front_cm`, rotated by `arc_rotation_deg`. `floor_coords_cm.lateral_cm` → x and
`out_from_front_cm` → −y. `height_cm` is the lens height above the mug shelf (→ z), each stop faces the arc centre,
and `tilt_deg` is the downward pitch.

The drafts have no roll. Every stop gets the roll fitted at P3 (1.98°), as `arc_far.py` assumed; override with
`roll_deg`.

Cameras are pinholes: square pixels, f = 1731.26 px at 2304×1296, principal point (W/2, H/2), and pixel i covers
[i, i+1). The fitted radial k1 = 0.0564 is applied only by `Camera.project(..., distort=True)`. MuJoCo renders a
pinhole.

## How to run

MuJoCo is **not** a project dependency (it is not in `pyproject.toml` / `uv.lock`), so run it in a throwaway uv env.
Run it on the Jetson; the GB10's Python deps belong to the project env only.

```
cd <repo>
# the tests (MuJoCo tests skip without mujoco)
uv run --no-project --python 3.13.5 --with numpy==2.5.3 --with opencv-python-headless==5.0.0.93 \
    --with mujoco==3.17.0 python -m unittest discover -s tests -t .
# per-stop visible fractions and patterns for every design occluder (vs the geometry's intended pattern)
MUJOCO_GL=egl uv run --no-project --python 3.13.5 --with numpy==2.5.3 --with mujoco==3.17.0 \
    python -m sim.mujoco_rig fractions --positions data/raw/2026-10-10_far-camera/positions_far_A_draft.json
# RGB + label PNGs per stop, or the MJCF
MUJOCO_GL=egl uv run ... python -m sim.mujoco_rig render --positions <draft> --occluder pick_S8 --out-dir /tmp/r --labels
MUJOCO_GL=egl uv run ... python -m sim.mujoco_rig mjcf --positions <draft> --out rig.xml
```

From Python:

```python
from sim import rig as R, mujoco_rig as MR
rig = R.load_rig("configs/rig_geometry.json", "data/raw/2026-10-10_far-camera/positions_far_A_draft.json",
                 occluder="pick_S8", mug_z=0.24)
with MR.MujocoRig(rig) as mr:
    print([r["fraction"] for r in mr.fractions("mug")])      # [1.0, 1.0, 0.0, 1.0, 1.0] -> CCHCC
```

`MUJOCO_GL=egl` is the headless default. `sim/mujoco_rig.py` sets it if unset, which works only if it is imported
before `mujoco` itself. On the Jetson a 2304×1296 label render with id mapping takes about 0.1 s
(`data/raw/2026-11-02_sim/tables.md`, `crosscheck.txt`).

## Scene spec for other backends

`export_scene_spec(rig)` writes the scene MuJoCo builds from the same `Rig` object as plain JSON (schema
`cmpe249.sim-scene.v1`, metres, the frame above). It is for backends that cannot import `sim/rig.py`, such as Isaac Sim
in its own Python 3.12 env on the GB10:

```
uv run --no-project --python 3.13.5 --with numpy==2.5.3 python -m sim.rig \
    --positions data/raw/2026-10-10_far-camera/positions_far_A_draft.json --occluder pick_S8 --scene-out scene.json
```

Keys:

- `boxes`: name, role (shelf / occluder / tag_card), label, center, half, quat_wxyz, material.
- `meshes`: the mug body and handle in world coordinates, role `target`.
- `tags`: id, dictionary, corners in TL, TR, BR, BL order as seen from the front, in the front plane, plus size_m.
- `cameras`: position, unit forward / up / right with right = forward × up, f_px, width, height, principal point.
- `labels`: the object grouping for segmentation.
- `materials`: render-default colours.
- `provenance`: the geometry and positions files, and each block's sources.

MuJoCo draws the tag markers 0.6 mm and the cards 0.3 mm in front of the front plane to avoid z-fighting.
`tests/test_sim_mujoco.py` checks that every exported box and camera matches the compiled MJCF.

## Isaac Sim backend (`sim/isaac_rig.py`)

Isaac Sim 6.2 runs only on the GB10: NVIDIA supports its aarch64 build on DGX Spark, but not on the Jetson. It lives
in its own Python 3.12 env, outside the repo and the project env; the student approved the separate env and NVIDIA's
licence on 2026-11-02.

```
# install once (18 GB): pip-style cross-index matching and an explicit pre-release pin are needed with uv
cd ~/cmpe249-sim/isaacsim-6.2 && uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python "isaacsim[all,extscache]==6.2.0.0" "tinyobjloader==2.0.0rc13" \
    --extra-index-url https://pypi.nvidia.com --index-strategy unsafe-best-match
# run: copy sim/isaac_rig.py, a scene spec (python -m sim.rig --scene-out) and the tag PNGs to the GB10
LD_PRELOAD=/lib/aarch64-linux-gnu/libgomp.so.1 OMNI_KIT_ACCEPT_EULA=YES \
  uv run --no-project --python ~/cmpe249-sim/isaacsim-6.2/.venv/bin/python isaac_rig.py \
  --scene scene.json --tags-dir tags --out out --lighting L1 L2 \
  [--target-asset ycbv/models/obj_000014.ply] [--extra-asset ycbv/models/obj_000012.ply@x,y,yaw,z]
```

- **Running headless needs three things:** the libgomp preload (aarch64), explicit USD lights (headless has none), and
  about 200 `app.update()` settle frames before the first capture.
- **Timings:** boot is about 8 s and the first settle about 100 s (one-time shader compile). After that, all five
  stops take about 4 s.
- **Masks** come from `instance_id_segmentation`: integer ids, not colours, so the MSAA problem above does not apply.
  The `occlusionRatio` field returns −1 for these prims on 6.2 and is not used.
- **Agreement with MuJoCo:**
  - Toy scene: P1 13,163 vs 13,162 visible pixels, and every stop within 0.012 in visible fraction.
  - Option A with `pick_S8`: CCHCC (1, 1, 0, 1, 1) in both, and the analytic model agrees
    (`data/raw/2026-11-02_sim/isaac_rig_A/`).
- **Rendered tags work with the rig's code.** `capture/tags.py` decodes them with the right ids, and registers L2 onto
  L1 at 0.117 px RMS.
- **`--target-asset` swaps in a textured model** (YCB-Video BOP PLY, mm), placed on the measured mug's base. It
  changes the geometry: the YCB mug is 8.1 cm tall against the study mug's 5.7 cm, so S8 left 30 % of it visible at
  P3. Visibility labels must therefore always come from the rendered scene, never from the design table.
- **Lighting presets L1/L2** are rough stand-ins (dome + two area lights; L2 turns one off), not photometric models.
  There is no room or floor yet: the background is the dome.

### Placement rules (unchanged)

- The target is one of the configured YCB-V models (tomato soup can, potted meat can, mug, foam brick, tuna can). It sits in
  #3, and every stop sees it whole. Which model a slot gets is decided by its class (below).
- 2-5 distractors stand in #3 / #4 and never hide the target.
- The occluder families are S8 / M16 / IND28 boards, a white box sized to the target's P3 footprint (the pilot-2 case), and
  YCB boxes. The occluder hides the target's convex hull from P3. Every family except IND28 leaves at least 2 stops where
  the hulls do not touch, so a removed episode can reach the k = 2 rule. IND28 covers every stop and is predeclared
  indistinguishable.
- The parked pose hides nothing, and it is outside the target's context window at every stop.

### Quota slots

The occluder family is not drawn. `slot_list(ctx, split)` expands the quota table of the config (`configs/sim/arrange_shelf_v3.json` by default; v2 has the same table and seeds as v1)
(shelf dev 60: S8 12, M16 18 = 9 L + 9 R, IND28 6, white box 12, YCB box 12; test 100: 20 / 30 = 15 + 15 / 10 / 20 / 20),
shuffles it with a seeded Fisher-Yates permutation and gives slot *i* the primary seed `primary_seed_start + i`. The list
depends only on the config content, not on dict order. The test list can be inspected, but no test arrangement is generated
(`check_dev_seed` refuses seeds >= 100000).

- **Tries.** A try is `(seed, attempt)`: attempt 0 is the plain seed, attempts 1..`retry_max` (20, in the config) are the
  deterministic retries.
- **Targets are slots too (shelf_v2 and v3).** `slot_list` gives every slot its target model. Within each class (S8, M16-L, M16-R,
  IND28, white box, YCB box; the two M16 sides are separate) the targets come from a seeded balanced list over the models the
  class can place (`slots.target_assignment.classes`): n slots over k models give each n // k, and n % k models one more,
  those with the lowest running total over the classes already done, so totals are as even as the class sizes allow. A failed
  try retries the same (family, side, target), then the family's reserve seeds; it never changes the target. shelf_v1 drew the
  target per try, so retries redrew it and the target became a function of the family. Pairs no placement can serve are
  listed under `excluded` in the config with their reason.
- **Reserve.** If all 21 tries of a seed fail, the next unused seed of the same family's reserve list is tried the same way
  (the reserve list of a family is consumed in slot order; a subset run resolves the earlier slots of its families so it
  reproduces the full run). An exhausted list is an error. **A slot never changes family, M16 side or target**; the old fallback
  (SD0001 of `shelf_dev_v0`, M16 to IND28) is gone.
- **Logging.** Every failed try (seed, attempt, reason, target model) and every replacement is in the arrangement's `slot`
  record and in `ARR/index/generation_log.json` (also copied into the set by `sim.episodes --generation-log`).
- **Names.** The id is `SD` + the seed that was used (`SD1003`); the slot index is in the record.
- **Design cases.** DES0-DES3 stay predeclared dev checks outside the 60, written to separate manifests.

### Asymmetric M16

**Side**, seen from the cameras (rig frame, +x = image right at the start stop P3): the sign of the board's lateral
displacement from the sight line P3 to the target centre, measured on the board's plane. **R** = board centre displaced
toward +x by `side_shift_m` (a magnitude of 1-6 cm), **L** = toward -x. The covered stops then lie toward that side of the
arc: R hides P3 and P4 (CCHHC), L hides P2 and P3 (CHHCC). The slot gives the side. A draw is accepted only if, on the
analytic hull coverage: P3 is hidden (>= 0.95), the adjacent stop on the board's side is covered >= `adjacent_min` (shelf_v2 / v3:
0.95, hidden; shelf_v1: 0.5, which rendered a partial `p` there on 4 of 9 M16-L boards), the nearest stop on the other side is
covered <= `opposite_near_max` (0.10, so it renders as a C view), every further stop on the other side is clear (hulls do not
touch), and (as for every resolvable family) at least 2 stops are clear. **The far same-side stop (P1 for L, P5 for R) is free in
shelf_v3**: partial cover there is accepted, so pHHCC and CCHHp boards are still one-sided (shelf_v2 limited it with
`same_far_max` 0.10). `pick_M16+3` (DES1) is R and `pick_M16-5` (DES2) is L, with fixed templates.

**Height.** shelf_v3 and shelf_v1 use the physical board, 0.12 m (width 16 cm, thickness 0.5 cm), so the simulated M16 matches
the physical 10-10 board. shelf_v2 used a 15 cm simulation variant (`height_m`), the tallest the ceiling clearance admits (0.165 -
0.015 = 0.150 m); it admitted no target the 12 cm board does not. `python -m sim.feasibility scan` (evidence in
`SIM/shelf_v3_geometry/height_scan.out`, v3 rules, 60 placements per target and side, ceiling removed): the tuna can is feasible
from 0.10 m and the foam brick from 0.10 m (87 / 161 combinations at 0.11 m, 204 / 250 at 0.12 m, saturated by 0.13 m); the
tomato soup can has no placement at any height up to 0.25 m; the potted meat can and the mug have rare left-side placements
only for boards taller than the physical one (meat can from 0.13 m, 1-2 combinations; mug from 0.14 m, 2), none on side R. The
limit for the tall targets is the side rule together with the 2-clear-stop rule for a 16 cm board, not the height. In the
generator search itself (`SIM/shelf_v3_geometry/matrix_100_tall.json`) the tomato soup can, the potted meat can and the mug had no
valid placement in 0 of 100 tries on either side, so M16 slots take the foam brick and the tuna can; zero in N tries is not a
proof. The rendered patterns are reported after rendering; the generator test only checks the analytic rule.

### Revisit noise (query captures only)

Each arrangement records, for every stop, one bounded uniform draw (`revisit` in the arrangement, `scene.revisit_cameras`
for the renderer): translation within +-10 mm on each world axis and rotation within +-0.5 deg about the camera's own yaw
(heading), pitch (downward pitch) and roll axes, added to the nominal pose. Ranges are in the config (`revisit`). The draw
is seeded by `(arrangement seed, stop, attempt)` and is the same for the visible, occluded and removed phases, both
lightings and every policy. References use the nominal cameras. A draw that would put the #3 outline or one of the four tags
outside the frame (`sim/rig.py frame_margins`, fitted k1, min margin >= 0, the nominal check) is redrawn with `attempt + 1`;
rejected draws are logged. P1 and P5 have the narrowest pitch windows (0.80 and 0.97 deg wide against the +-0.5 deg range),
so most redraws are there. **Tag-free scenes (shelf_v3):** the check is the #3 outline (the front opening) and the target's
projected hull inside the frame, margin >= 0 with the fitted k1 (`frame_check`), for the nominal and the revisit poses. The per-stop
pitch values of `positions_shelf_A.json` are unchanged (that file is not edited: shelf_v1 / v2 arrangements record its sha256); they
were chosen to keep #3 and the four tags in frame, and #3 in frame is what remains of that rationale. On the 60 dev slots plus
DES0-3 (`SIM/shelf_v3_geometry/redraw_rate.txt`) the same draws are rejected 89 times at 52 of 320 stops under the tag rule (P1 55,
P5 34) and never under the tag-free rule.

### Hash provenance

`arrangement_sha256` is the hash of the arrangement without its `unhashed` block (the config path as the caller spelled it,
the file's byte hash and the Python version), and the config hash is that of the config's canonical JSON, so the hash
depends only on the seed (and attempt, family, side), the config content, the code and input files whose sha256 the
provenance records, and numpy's version.

### Jobs, labels and sets

- **Jobs:**
  - `jobs_refL1.json` is the **primary** run: every query, L1 and L2, against the L1 reference at its stop.
  - `jobs_same.json` is a **secondary**, separate run, reported separately, with each query against its own lighting's
    reference.
  - Results are reported separately for L1 and L2 queries; the lighting is in every episode_id.
  - The design cases have their own `*_design*` files.
- **Evidence annotation.** The expected box stays the reference's (nominal camera). With tags (shelf_v1 / v2) the evidence step
  registers each query to its reference through the four tags. **shelf_v3 scenes have no tags** (2026-11-03: no fiducials on a home
  robot's shelf): evidence v0.3 aligns the query itself, frozen v0.2.1 falls back to no alignment when it finds no tags.
- **True alignment (`true_alignment.json`, `true_alignment_design.json`).** From the known reference (nominal) and query (revisit)
  camera poses, `sim/alignment.py` gives per (arrangement, stop) the exact homography `H` (3 x 3, row-major, `H[2][2]` = 1)
  that maps a homogeneous QUERY pixel `(u, v, 1)` to the REFERENCE pixel, for two world planes: `H_front_plane` (y = 0, the shelf
  front plane where the tags were) and `H_target_plane` (y = the target's centre depth, `target_plane_y_m`). Pixels are continuous,
  origin at the image's top-left corner, u right, v down, pixel i covers [i, i + 1) (as the annotation boxes); the cameras are the
  rendered pinhole cameras (no distortion). Each stop also has `pose_delta` (dx, dy, dz in m, dyaw, dpitch, droll in deg),
  `reference_box` (the L1 reference mask's box) and `box_corner_displacement_px` per plane (|H^-1 c - c| for the 4 box corners: what no
  alignment would leave). One H serves L1 and L2 queries and all three conditions. **Evaluation-only**: marked
  `evaluation_only` and `never_an_evidence_or_policy_input`, like `view_labels.json`. On the v2 check set (which has tags) the true
  front-plane H agrees with the tag-based `capture/tags.py align` H within 0.58 px (25 views, central 60 % of the frame;
  `SIM/shelf_v3_geometry/valid_align.txt`).
- **Labels:** come only from the rendered instance masks (`labels.json`), never from the generator's geometry.
  - Visible fraction at a query stop = target pixels with the scene / target pixels with everything else hidden, both at that
    stop's revisit pose (`masks/target_alone_revisit_<stop>.png`). The reference uses the nominal pose.
  - Removed views: occluder coverage of the target's **region**, taken from the visible-phase capture at the same pose (target
    present, occluder parked), not from the nominal reference mask.
  - Cut-offs as in `docs/SIM_PREREGISTRATION.md` section 3: diagnostic = visible fraction >= 0.90, or occluder covers < 10 %
    of the region.
  - **Label sanity (`labels.json` `label_sanity`, `ok`):** in the visible phase every stop must show at least 0.9 x its
    target-alone pixels at the same revisit pose. A lower ratio means the shelf or a distractor hides the target, which the
    generator rules prevent, and the removed views would get a small region. The renderer prints a WARNING, `check_batch`
    flags the arrangement (and exits 1), and `set.json` lists it under `label_sanity_flagged`.
- **Manifest:** `manifest.json` has `"simulation": true` at the top level, and each arrangement carries `occluder_family`,
  `m16_side` and `design_case` next to `ArrangementRecord.to_dict()`'s keys. `verify.manifest.ArrangementRecord` validates them and builds the bootstrap strata from them
  (the family, M16 split by side as `M16-L` / `M16-R`, and `design:<family>` for DES0-3).
- **Safe re-rendering:**
  - `isaac_batch.py` renders into `OUT/<ARR>.partial` and renames it into place.
  - `--skip-existing` skips an arrangement only if its `labels.json` records the sha256 of the arrangement file given now
    **and** the sha256 of `isaac_batch.py` and `isaac_rig.py`, the same lighting set, the same render settings
    (`render_settings()`: resolution, renderer, rt subframes, settle / capture updates, lighting presets, materials, Isaac
    version, `models_info.json`, tag images; hash in `labels.hashes.render_settings_sha256`, full record in `render.json`),
    and every phase x stop x lighting PNG. Anything else re-renders, with the reason printed (an L1-only folder resumed with
    L1 + L2; a label-code fix).
  - `episodes` raises on a folder with `arrangement.json` but no `labels.json`, a leftover `.partial`, a labels file from another
    arrangement file, a `--positions` file other than the one the arrangements recorded (hash and stop names), and a set
    whose arrangements come from more than one generator or config sha256. `set.json` `n_episodes` counts the rendered
    lightings.
- **Render history (found 2026-11-03):** real-time RTX keeps per-pixel history in each render product.
  - With one set of render products for all phases, a target hidden for the removed phase left a target-shaped trace
    (+1.5 to +2.7 grey levels) for 100+ frames. The trace also appeared on the occluder's face in front of it, and
    turning temporal AA off did not change it (`data/raw/2026-11-03_sim_pilot/ghost_test*.py`).
  - `isaac_batch.py` therefore creates new render products for every (phase, lighting) capture, with 100 updates
    before each. Toggling visibility on one set of render products is not safe for removed / occluded views.

## Visible fraction

The visible fraction of a target is target pixels with nothing hidden, divided by target pixels with everything else
hidden. The second render moves the other geoms to group 5, which MuJoCo does not draw by default.

This is a projected-area measure. The analytic model instead weighs a flat silhouette card plus the full rim disc, so
its denominator is 5.5–6.5% larger (49.1–49.4 vs 46.1–46.8 cm² at the mug, without the handle). Partial values near a
class boundary can therefore differ by a few thousandths. Classes: H ≤ 0.05, C ≥ 0.90, else p.

**Segmentation needs `offsamples=0`.** MuJoCo encodes object ids as flat colours. Multisampling blends them at edges
into colours that decode to *other* objects: with 4× MSAA, stray tag ids appeared along the mug outline, and the mug
lost 0.2–0.4% of its pixels. `MujocoRig` therefore defaults to 0 and refuses label renders on a multisampled context.
Use a second `MujocoRig(rig, offsamples=4)` for smooth RGB previews. Any colour-coded segmentation (Isaac included)
needs the same care.

## Limits

- **Mug.** The mug is a closed solid of revolution of the measured `frame` silhouette (the top cap stands in for the
  rim opening). The handle is a solid plate with no hole, 2 cm out from the body over z 1.0–5.3 cm. Its 1.0 cm
  thickness is **assumed** (not measured).
- **Handle effect.** At the outer stops the plate sticks out past the narrow lower body. It adds 6–9% to the mug's
  projected area at option A's P1/P5 (3.5–6% at B20's). An occluder edge on the handle side therefore cuts
  visibility 1–5 points deeper than the analytic model predicts, because that model counts handle area only where it
  clears the body at the same height.
- **Not modelled.**
  - Below #3 (compartment #2, where tags 0/1 hang).
  - Above #4 (where tags 2/3 stand).
  - The neighbouring shelving left of the unit, which may block P1 in option A.
  - The room, and the other props.
- **Approximate inputs.**
  - Tag positions are back-projected from one detection and were never taped (sides 4.84–5.16 cm vs the 5.0 cm print).
  - Board and side thickness come from the pose fit.
  - The back panel thickness is a placeholder.
- **Camera.**
  - Pinhole only, with no k1 in renders.
  - Roll is the P3 fit's value at every stop.
  - The lens pose is the 2026-10-10 fit from before the bump (`design_far.md`).
- **Statics only.** No physics: the "mocap" bodies exist only to move the mug and occluder between renders.

### Known gaps in the generator and batch (checkpoint 2, 2026-11-03)

The PR #4 review findings on the occluder family, hash provenance, `index.json`, re-renders, incomplete folders and the
positions copy are fixed in checkpoint 2 (above). Still open:

- **One-sidedness is an analytic rule.** The M16 side rule is checked on projected convex hulls at the nominal poses; the
  rendered pattern at the revisit poses can differ (reported by `sim/check_batch.py`).
- **M16 targets are limited by the side rule, not by the board's height** (shelf_v2 and v3, see "Asymmetric M16"): for the tomato soup
  can, the potted meat can and the mug no valid placement was found in the tested generator search (0 of 100 tries on either side;
  the finer height scan found rare left-side placements of boards taller than the physical one, so this is not a proof), so M16
  slots take the foam brick and the tuna can only. Which pairs the other classes admit is in the config's
  `slots.target_assignment` and `notes/2026-11-03-m16-and-render-check.md`.
- **The revisit check is at the nominal margin (>= 0 px), not with a safety margin.** The #3 outline or the target's hull can sit a
  pixel from the frame edge in a query view (with tags, a tag corner could).
- **True alignment is exact for two planes only.** `true_alignment.json` gives the homography of the front plane and of the target's
  depth plane; the rest of the shelf interior moves by parallax, so an image-based alignment is scored against these, not against
  a per-pixel truth.
