# sim/: simulated shelf rig

## What it is for

- **Camera-position design.** Check drafted arc stops and occluder placements on a 3-D model before taping stops or
  cutting occluders. Questions it answers: does the occluder hide the mug from this stop, are #3 and the tags inside
  the frame, how much margin is left?
- **Visibility labels.** Per-object visible fractions and H/C/p classes for candidate views, from exact segmentation.

- **Isaac Sim is the study's simulator; MuJoCo is the cross-check.** The MuJoCo backend stays as an independent geometry check, run on request only (student, 2026-11-02).
- **The course study's test bed (decision 2026-11-02).** The student moved the study from physical capture to
  simulation ([`docs/SIMULATION_STUDY.md`](../docs/SIMULATION_STUDY.md)). Realistic images then come from the Isaac Sim
  backend, and both backends give exact labels.

**MuJoCo is not an appearance model.** Its colours are flat render defaults, and textures, materials, lighting, lens
blur, noise and the real props are not modelled. Do not read detector scores, DINOv2 matches or "how the photo will
look" from a MuJoCo render; use the Isaac Sim backend for appearance.

## Coordinate frame

The frame is in metres and right-handed, as in `configs/rig_geometry.json` → `frame`:

- **x** is lateral, + right as seen from the camera, 0 on the #3 centre line.
- **y** is depth behind the #3 front plane, + into the shelf.
- **z** is height above the mug-shelf top (the top of #3's floor board).

The analytic design scripts (`geom_measured.py`, `geom_far.py`) use cm with (x_a lateral, y_a height, z_a depth), so
`(x, y, z) = (x_a, z_a, y_a) / 100`. "The mug at z = 24" in `design_far.md` is `load_rig(..., mug_z=0.24)`, the
mug's y coordinate.

Positions drafts (`cmpe249.positions.v1`) place the lens on an arc of radius R about a centre on x = 0, at
`arc_centre_behind_front_cm`, rotated by `arc_rotation_deg`. `floor_coords_cm.lateral_cm` → x and
`out_from_front_cm` → −y. `height_cm` is the lens height above the mug shelf (→ z), each stop faces the arc centre,
and `tilt_deg` is the downward pitch.

The drafts have no roll. Every stop gets the roll fitted at P3 (1.98°), as `arc_far.py` assumed; override with
`roll_deg`.

Cameras are pinholes: square pixels, f = 1731.26 px at 2304×1296, principal point (W/2, H/2), and pixel i covers
[i, i+1). The fitted radial k1 = 0.0564 is applied only by `Camera.project(..., distort=True)`. MuJoCo renders a
pinhole.

## How to run

MuJoCo is **not** a project dependency (it is not in `pyproject.toml` / `uv.lock`), so run it in a throwaway uv env.
Run it on the Jetson; the GB10's Python deps belong to the project env only.

```
cd <repo>
# the tests (MuJoCo tests skip without mujoco)
uv run --no-project --python 3.13.5 --with numpy==2.5.3 --with opencv-python-headless==5.0.0.93 \
    --with mujoco==3.17.0 python -m unittest discover -s tests -t .
# per-stop visible fractions and patterns for every design occluder (vs the geometry's intended pattern)
MUJOCO_GL=egl uv run --no-project --python 3.13.5 --with numpy==2.5.3 --with mujoco==3.17.0 \
    python -m sim.mujoco_rig fractions --positions data/raw/2026-10-10_far-camera/positions_far_A_draft.json
# RGB + label PNGs per stop, or the MJCF
MUJOCO_GL=egl uv run ... python -m sim.mujoco_rig render --positions <draft> --occluder pick_S8 --out-dir /tmp/r --labels
MUJOCO_GL=egl uv run ... python -m sim.mujoco_rig mjcf --positions <draft> --out rig.xml
```

From Python:

```python
from sim import rig as R, mujoco_rig as MR
rig = R.load_rig("configs/rig_geometry.json", "data/raw/2026-10-10_far-camera/positions_far_A_draft.json",
                 occluder="pick_S8", mug_z=0.24)
with MR.MujocoRig(rig) as mr:
    print([r["fraction"] for r in mr.fractions("mug")])      # [1.0, 1.0, 0.0, 1.0, 1.0] -> CCHCC
```

`MUJOCO_GL=egl` is the headless default. `sim/mujoco_rig.py` sets it if unset, which works only if it is imported
before `mujoco` itself. On the Jetson a 2304×1296 label render with id mapping takes about 0.1 s
(`data/raw/2026-11-02_sim/tables.md`, `crosscheck.txt`).

## Scene spec for other backends

`export_scene_spec(rig)` writes the scene MuJoCo builds from the same `Rig` object as plain JSON (schema
`cmpe249.sim-scene.v1`, metres, the frame above). It is for backends that cannot import `sim/rig.py`, such as Isaac Sim
in its own Python 3.12 env on the GB10:

```
uv run --no-project --python 3.13.5 --with numpy==2.5.3 python -m sim.rig \
    --positions data/raw/2026-10-10_far-camera/positions_far_A_draft.json --occluder pick_S8 --scene-out scene.json
```

Keys:

- `boxes`: name, role (shelf / occluder / tag_card), label, center, half, quat_wxyz, material.
- `meshes`: the mug body and handle in world coordinates, role `target`.
- `tags`: id, dictionary, corners in TL, TR, BR, BL order as seen from the front, in the front plane, plus size_m.
- `cameras`: position, unit forward / up / right with right = forward × up, f_px, width, height, principal point.
- `labels`: the object grouping for segmentation.
- `materials`: render-default colours.
- `provenance`: the geometry and positions files, and each block's sources.

MuJoCo draws the tag markers 0.6 mm and the cards 0.3 mm in front of the front plane to avoid z-fighting.
`tests/test_sim_mujoco.py` checks that every exported box and camera matches the compiled MJCF.

## Isaac Sim backend (`sim/isaac_rig.py`)

Isaac Sim 6.2 runs only on the GB10: NVIDIA supports its aarch64 build on DGX Spark, but not on the Jetson. It lives
in its own Python 3.12 env, outside the repo and the project env; the student approved the separate env and NVIDIA's
licence on 2026-11-02.

```
# install once (18 GB): pip-style cross-index matching and an explicit pre-release pin are needed with uv
cd ~/cmpe249-sim/isaacsim-6.2 && uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python "isaacsim[all,extscache]==6.2.0.0" "tinyobjloader==2.0.0rc13" \
    --extra-index-url https://pypi.nvidia.com --index-strategy unsafe-best-match
# run: copy sim/isaac_rig.py, a scene spec (python -m sim.rig --scene-out) and the tag PNGs to the GB10
LD_PRELOAD=/lib/aarch64-linux-gnu/libgomp.so.1 OMNI_KIT_ACCEPT_EULA=YES \
  uv run --no-project --python ~/cmpe249-sim/isaacsim-6.2/.venv/bin/python isaac_rig.py \
  --scene scene.json --tags-dir tags --out out --lighting L1 L2 \
  [--target-asset ycbv/models/obj_000014.ply] [--extra-asset ycbv/models/obj_000012.ply@x,y,yaw,z]
```

- **Running headless needs three things:** the libgomp preload (aarch64), explicit USD lights (headless has none), and
  about 200 `app.update()` settle frames before the first capture.
- **Timings:** boot is about 8 s and the first settle about 100 s (one-time shader compile). After that, all five
  stops take about 4 s.
- **Masks** come from `instance_id_segmentation`: integer ids, not colours, so the MSAA problem above does not apply.
  The `occlusionRatio` field returns −1 for these prims on 6.2 and is not used.
- **Agreement with MuJoCo:**
  - Toy scene: P1 13,163 vs 13,162 visible pixels, and every stop within 0.012 in visible fraction.
  - Option A with `pick_S8`: CCHCC (1, 1, 0, 1, 1) in both, and the analytic model agrees
    (`data/raw/2026-11-02_sim/isaac_rig_A/`).
- **Rendered tags work with the rig's code.** `capture/tags.py` decodes them with the right ids, and registers L2 onto
  L1 at 0.117 px RMS.
- **`--target-asset` swaps in a textured model** (YCB-Video BOP PLY, mm), placed on the measured mug's base. It
  changes the geometry: the YCB mug is 8.1 cm tall against the study mug's 5.7 cm, so S8 left 30 % of it visible at
  P3. Visibility labels must therefore always come from the rendered scene, never from the design table.
- **Lighting presets L1/L2** are rough stand-ins (dome + two area lights; L2 turns one off), not photometric models.
  There is no room or floor yet: the background is the dome.

## Generated arrangements and dev sets (2026-11-03)

The simulated capture mirrors `capture/run_arrangement.py`: phases reference (target in place, occluder parked),
visible, occluded (occluder placed) and removed (target removed, occluder exactly as in occluded), each at every stop
under L1 and L2.

```
# Jetson: arrangements (dev seeds 0-9999 only) + the design cases
uv run --no-project --python 3.13.5 --with numpy==2.5.3 python -m sim.arrange --seeds 0-5 --design --out ARR
# GB10: copy sim/isaac_batch.py next to isaac_rig.py in ~/cmpe249-sim/run/, then
LD_PRELOAD=/lib/aarch64-linux-gnu/libgomp.so.1 OMNI_KIT_ACCEPT_EULA=YES ~/.local/bin/uv run --no-project \
  --python ~/cmpe249-sim/isaacsim-6.2/.venv/bin/python isaac_batch.py --arrangements ARR/*.json \
  --assets-dir ../assets/ycbv/models --tags-dir tags --out OUT
# Jetson, on the set's final location (paths in jobs and annotations are absolute)
uv run --no-project --python 3.13.5 --with numpy==2.5.3 --with opencv-python-headless==5.0.0.93 \
  python -m sim.episodes --root SET --contact-sheets
```

- **Generator rules:**
  - The target is one of the configured YCB-V models (tomato soup can, potted meat can, mug, foam brick, tuna can).
    It sits in #3, and every stop sees it whole.
  - 2-5 distractors stand in #3 / #4 and never hide the target.
  - The occluder families are S8 / M16 / IND28 boards, a white box sized to the target's P3 footprint (the pilot-2
    case), and YCB boxes. The occluder hides the target's convex hull from P3. Every family except IND28 leaves at
    least 2 stops where the hulls do not touch, so a removed episode can reach the k = 2 rule. IND28 covers every
    stop and is predeclared indistinguishable.
  - The parked pose hides nothing, and it is outside the target's context window at every stop.
- **Jobs:**
  - `jobs_refL1.json` is the **primary** run: every query, L1 and L2, against the L1 reference at its stop.
  - `jobs_same.json` is a **secondary**, separate run, reported separately, with each query against its own
    lighting's reference.
  - Results are reported separately for L1 and L2 queries; the lighting is in every episode_id.
- **Labels:** come only from the rendered instance masks (`labels.json`), never from the generator's geometry.
- **Render history (found 2026-11-03):** real-time RTX keeps per-pixel history in each render product.
  - With one set of render products for all phases, a target hidden for the removed phase left a target-shaped trace
    (+1.5 to +2.7 grey levels) for 100+ frames. The trace also appeared on the occluder's face in front of it, and
    turning temporal AA off did not change it (`data/raw/2026-11-03_sim_pilot/ghost_test*.py`).
  - `isaac_batch.py` therefore creates new render products for every (phase, lighting) capture, with 100 updates
    before each. This takes about 2 min per arrangement instead of about 1 min. Toggling visibility on one set of
    render products is not safe for removed / occluded views.

## Visible fraction

The visible fraction of a target is target pixels with nothing hidden, divided by target pixels with everything else
hidden. The second render moves the other geoms to group 5, which MuJoCo does not draw by default.

This is a projected-area measure. The analytic model instead weighs a flat silhouette card plus the full rim disc, so
its denominator is 5.5–6.5% larger (49.1–49.4 vs 46.1–46.8 cm² at the mug, without the handle). Partial values near a
class boundary can therefore differ by a few thousandths. Classes: H ≤ 0.05, C ≥ 0.90, else p.

**Segmentation needs `offsamples=0`.** MuJoCo encodes object ids as flat colours. Multisampling blends them at edges
into colours that decode to *other* objects: with 4× MSAA, stray tag ids appeared along the mug outline, and the mug
lost 0.2–0.4% of its pixels. `MujocoRig` therefore defaults to 0 and refuses label renders on a multisampled context.
Use a second `MujocoRig(rig, offsamples=4)` for smooth RGB previews. Any colour-coded segmentation (Isaac included)
needs the same care.

## Limits

- **Mug.** The mug is a closed solid of revolution of the measured `frame` silhouette (the top cap stands in for the
  rim opening). The handle is a solid plate with no hole, 2 cm out from the body over z 1.0–5.3 cm. Its 1.0 cm
  thickness is **assumed** (not measured).
- **Handle effect.** At the outer stops the plate sticks out past the narrow lower body. It adds 6–9% to the mug's
  projected area at option A's P1/P5 (3.5–6% at B20's). An occluder edge on the handle side therefore cuts
  visibility 1–5 points deeper than the analytic model predicts, because that model counts handle area only where it
  clears the body at the same height.
- **Not modelled.**
  - Below #3 (compartment #2, where tags 0/1 hang).
  - Above #4 (where tags 2/3 stand).
  - The neighbouring shelving left of the unit, which may block P1 in option A.
  - The room, and the other props.
- **Approximate inputs.**
  - Tag positions are back-projected from one detection and were never taped (sides 4.84–5.16 cm vs the 5.0 cm print).
  - Board and side thickness come from the pose fit.
  - The back panel thickness is a placeholder.
- **Camera.**
  - Pinhole only, with no k1 in renders.
  - Roll is the P3 fit's value at every stop.
  - The lens pose is the 2026-10-10 fit from before the bump (`design_far.md`).
- **Statics only.** No physics: the "mocap" bodies exist only to move the mug and occluder between renders.

### Known gaps in the generator and batch (PR #4 review, 2026-11-03; fixed in the next checkpoint before the dev renders)

- **Occluder family.** `sim/arrange.py` still draws the family from `family_weights` and falls back to the next family when a pair fails. In dev seeds 0–99, 27 arrangements changed family this way; SD0001 went from M16 to IND28. M16 has no side, so most M16 boards end up centred (pattern CpHpC). The quota slot list with within-family retries, reserve seeds and one-sided M16 (`docs/SIM_PREREGISTRATION.md` §2) replaces all of this. `shelf_dev_v0` is a development set from the old rule only.
- **Hash provenance.** `arrangement_sha256` covers the provenance block. That block holds the config path as the caller spelled it and the Python version, so identical arrangements can hash differently. For in-memory configs, the hash ignores the key order that `weighted_order` depends on.
- **Shell globs.** `python -m sim.arrange --out ARR` writes `ARR/index.json` next to the arrangements, so `isaac_batch.py --arrangements ARR/*.json` refuses the batch. Until the fix, pass the arrangement files explicitly.
- **Re-renders and incomplete folders.**
  - A re-render over an existing folder overwrites `arrangement.json` before `labels.json`. `--skip-existing` checks only that `labels.json` exists, so an interrupted re-render can mix old labels with new files.
  - `sim/episodes.py` silently skips folders without `labels.json`.
  - `sim/episodes.py` copies the `--positions` file without checking it against the positions hash each arrangement records.
- **Labels for select-v4.** `view_labels.json` (`cmpe249.sim-view-labels-set.v0`) is not yet readable by `verify.select`.
- **Simulation label.** The manifest carries no simulation flag, so `verify.run --manifest` labels sim results "REAL PILOT".
